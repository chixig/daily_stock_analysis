# R1 implementation and validation refinements
The first R1 computation uses code509737eb84d17f8c99de41ddbe87e152184c4f01, run35719405693. Before reading its economic results, static follow-up found that the audit scan attributed potential QC-suppressed windows to nominal accounts as well as restricted accounts. Nominal accounts never use that gate; the scan was corrected (no strategy orders change).
The causal engine now explicitly uses the retained next-session calendar when deciding whether a planned closing sale has a next session, rather than whether a future price row happens to be loaded. This enables a15:00 execution-prefix test without removing a valid sale merely because the prefix ends there. Full-history evaluation horizon is unchanged.
Opening price sanity additionally checks the already-known lower limit; it does not use future high/low/volume. Numeric order comparisons include cash_after and shares_after. Validation adds a closing-event cutoff and synthetic unknown-window, finite-cash and T+1 cases. These are implementation/validation refinements, not new factors, buffer values, optimized times or slippage levels. The frozen protocol and scenario registry remain unchanged. First-run outputs are retained by Git history; final results are rerun and independently compared.
